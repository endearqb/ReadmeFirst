# v2.1 → v2.2 迁移指南

> 面向 Agent 的无损升级清单：在保留目标项目本地规则的前提下，引入任务级别与风险领域的二维路由、可选 Profile 和能力包。

## 0. 升级原则

- v2.2 向后兼容 v2.1；没有安装任何 Profile 的项目仍按原 L0/L1/L2 流程工作。
- 不覆盖目标项目已有 `AGENTS.md`、README、Skill 或更严格安全规则。
- 不根据目录名静默安装大型能力包；必须有技术栈证据，并由用户或项目策略选择启用。
- Profile 只负责项目本地路由；Skill 只负责可复用专业工作流；二者都不能替代代码、测试、schema 和配置事实。

## 1. 更新 `AGENTS.md`

将首行版本印记更新为：

```md
<!-- README First protocol v2.2.0 -->
```

合并以下能力，不覆盖本地特化规则：

1. 第 0 节最小闭环从“定级 → 执行 → 记录”扩展为“定级 → 风险领域路由 → 执行 → 记录”。
2. 新增“风险领域与能力路由”章节，至少支持：
   - `database`
   - `transaction`
   - `concurrency`
   - `http-network`
   - `cache-overload`
   - `runtime-resources`
   - `authentication-authorization`
   - `security-privacy`
   - `migration-release`
   - `external-side-effects`
3. 读取规则加入 `.ai/profiles/` 与 Profile 指向的 Skill。
4. 明确优先级：项目本地规则和 Profile 高于通用 Skill。
5. 扩展 L2 触发：事务/锁/幂等、多租户授权、缓存隔离、资源上限、迁移发布和外部副作用。
6. 禁止把扫描器命中直接包装成已确认 finding，或把无命中包装成安全证明。

## 2. 更新 changes 模板

L1 增加：

```md
- 风险领域：（无则写“无”）
```

L2 增加：

```md
- 风险领域：
- 使用的 Profile / Skill：（无则说明原因）
- 业务不变量与信任边界：
- 风险对应证据：
  - 正确性：
  - 性能 / 资源：
  - 并发 / 重复：
  - 安全 / 隐私：
  - 迁移 / 恢复：
```

历史 changes 保留原样，不批量改写。

## 3. 可选创建 `.ai/profiles/`

只有在项目实际安装一个或多个能力包时创建：

```text
.ai/profiles/
└── <profile-id>.md
```

Profile 应包含（frontmatter 使用 `risk_domains`）：

- 唯一 `profile_id` 与版本；
- 风险领域；
- 触发条件；
- 必读项目上下文；
- 业务不变量与信任边界；
- 阻断条件；
- 最低验证证据；
- 对应 Skill 的项目安装路径。

可从 canonical `extensions/profile-template.md` 起步。

## 4. 安装可选能力包

以 Full-stack Foundations 为例：

```bash
mkdir -p .ai/profiles skills
cp extensions/fullstack-foundations/PROFILE.md \
  .ai/profiles/fullstack-foundations.md
cp -R extensions/fullstack-foundations/skill/fullstack-foundations-guard \
  skills/fullstack-foundations-guard
```

复制后必须：

1. 检查 `.ai/profiles/fullstack-foundations.md` 的 `install_skill_path` 与真实路径一致；
2. 填写目标项目真实的安装、lint、typecheck、test、build 和 migration 命令；
3. 依据目标项目技术栈删除不适用触发条件；
4. 不把培训手册加入每次任务默认上下文。

## 5. 更新标准扩展说明

在根 README、架构文档和目录模板中加入：

- `.ai/profiles/`：项目本地风险路由，按需启用；
- 项目 `skills/`：Profile 指向的可复用专业执行能力；
- canonical `extensions/`：能力包发布目录，不属于下游最小系统。

## 6. 更新时效戳语义

v2.2 推荐：

```md
> 更新于:YYYY-MM-DD
```

可以保留 v2.1 的旧格式，检查脚本仍兼容。若附加 commit，只能明确表示“核验基线”，不得把修改前 commit 冒充本文件所属提交。

## 7. 更新 Builder

Builder 升级后应：

1. 扫描真实技术栈证据；
2. 输出能力包候选及证据文件；
3. 默认只建议，不静默安装；
4. 用户选择安装时，复制 Profile 与 Skill 并做路径验证；
5. 不因发现 `package.json` 就自动判定项目需要全套 Node.js 后端能力包。

## 8. 更新 Maintainer

Maintainer 增加 Profile 与证据治理：

- Profile 指向的 Skill 是否存在；
- Profile 版本和风险领域是否有效；
- L2 changes 是否记录风险领域和风险对应证据；
- 同一风险反复出现时是否应沉淀到 README、Profile 或 decisions；
- 技术栈已移除但 Profile 仍激活时是否应停用。

## 9. 验证

升级后运行目标项目已有检查，并在 canonical ReadmeFirst 仓库运行：

```bash
bash tests/test-maintainer-scripts.sh
python3 tests/validate_repository.py
python3 -m py_compile \
  extensions/fullstack-foundations/skill/fullstack-foundations-guard/scripts/risk_scan.py
```

确认：

- `AGENTS.md` 版本印记与 `VERSION` 一致；
- builder 离线模板与根 `AGENTS.md` 同步；
- Profile 指向真实 Skill；
- v2.1 项目不安装 Profile 时仍可正常执行；
- 没有覆盖目标项目已有规则。

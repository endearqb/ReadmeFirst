# 0004 - v2.1 三项机制:验证证据、访谈模式、会话交接与脚本

## 背景

v2.0 已经实现了"重量与风险成正比",但在四个实战维度上仍有缺口:

1. **验证可信度**:Agent 经常在未实际运行验证的情况下声称完成。
2. **本质不确定性的主动压缩**:用户意图、业务规则、方案取舍这类"只存在于用户脑中"的不确定性,读代码无法消除,但原协议没有给出明确的处理通道。
3. **跨会话工作连续性**:长任务在会话边界处容易丢失上下文。
4. **框架自身的可升级性**:维护者需要可复现的巡检、选点和新鲜度检查手段。

## 决策

1. **验证证据门(轻量版)**:`.ai/changes/` 的"验证"字段改为"验证证据",要求包含实际运行的命令 + 关键输出摘录 + 结论;禁止行为第 7 条强化为"没有本次会话内新鲜验证证据不得声称完成"。
2. **访谈模式(grilling)并入协议**:归属 `AGENTS.md` §3.5,作为防御性提问规则的例外通道。当 L2 任务的不确定性主要来自用户意图/业务规则/取舍标准时,Agent 主动沿决策树逐层访谈,结论写入任务契约并按需沉淀。不新增独立 skill,保持"两技能一协议"结构。
3. **会话交接存于项目内**:新增 `.ai/handoff.md`,由 Agent 在会话暂停且任务未完成时写入,新会话开始时必读,任务完成后清空。内容引用其他文档路径而不复制,并脱敏。
4. **只读 bash 脚本支持维护**:在 `skills/readme-first-maintainer/scripts/` 提供 check-paths、check-freshness、dir-hotspots 三个脚本,输出数据供 Agent 判断,不直接修改仓库。Windows 环境经 Git Bash 运行。

## 影响

- `AGENTS.md` §3.5、§5.1、§5.5、§6、§7 需要相应修改。
- `skills/readme-first-maintainer/SKILL.md` 的巡检流程改为"脚本取数 + Agent 判断"。
- `skills/readme-first-builder/SKILL.md` 的选点逻辑改为热度×复杂度双因子。
- 根 `README.md` 与 `.ai/architecture/` 需要纳入 handoff、glossary、plans 的流向。

## 非目标

- 不接 CI,不引入构建链;脚本只读,判断和修改仍由 Agent 完成。
- 不采用 omo 式 .ai/evidence/ 重型证据目录;证据直接写在 changes 记录中。
- 不采用 superpowers 式"1% 可能就必须触发"的强制条款,保持"够用即停"。

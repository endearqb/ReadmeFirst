# 术语表

| 术语 | 定义 | 别名/易混淆项 |
|---|---|---|
| L0 / L1 / L2 | 任务分级:L0 轻量(1–2 文件显而易见修改)、L1 标准(单模块内常规任务)、L2 高影响(公共 API/数据结构/跨模块/安全等) | 与"风险四级表"(低/中/高/不可逆)不同,后者是剩余不确定性风险 |
| 偶然不确定性 | 来自"还没读文件/搜代码/看测试",可用工程动作消除 | 与本质不确定性相对 |
| 本质不确定性 | 来自问题本身(用户意图、业务规则、方案取舍),需通过访谈、假设、记录压缩 | 与偶然不确定性相对 |
| 验证证据 | changes 记录中必须包含的:实际运行的命令 + 关键输出摘录 + 结论 | 不是单纯的"验证方式"或"验证结果" |
| 访谈模式 | 当 L2 任务的不确定性主要来自用户脑中信息时,沿决策树逐层提问收敛 | 不是防御性提问的常规阻塞性问题 |
| 标准扩展 | `.ai/plans/`、`.ai/glossary.md`、`.ai/handoff.md`,按需启用,不进入最小系统 | 不是最小系统成员 |
| 版本印记 | 下游项目 `AGENTS.md` 首行的 `<!-- README First protocol vX.Y.Z -->` 注释 | 不是 `VERSION` 文件本身 |
| 热度 × 复杂度 | builder/maintainer 选点的双因子算法:热度 = 近 90 天提交触达;复杂度 = 文件数/行数/深度/大文件综合评分 | 不是单一 git 热度 |
| 够用即停 | 读取规则:当影响本次任务的偶然不确定性已被消除,就停止扩大阅读 | 不是"读完全部" |
| 时效戳 | 目录 README 与 `.ai/architecture/` 文件标题下的 `> 更新于:YYYY-MM-DD · commit <short-sha>` | 不是文件的 mtime 或 git log 时间 |
| 记忆压缩 | maintainer 将 30 天前的 changes 按月生成 digest,原件移入 archive | 不是删除历史记录 |
| 知识沉淀 | 将 changes 中反复出现的假设/约定/踩坑晋升为 README/architecture/decisions | 不是简单复制粘贴 |

# 术语表

| 术语 | 定义 | 别名 / 易混淆项 |
|---|---|---|
| L0 / L1 / L2 | 任务级别：决定读取范围、任务契约、记录深度和最终输出的流程重量 | 不等于风险领域，也不同于“低 / 中 / 高 / 不可逆”的剩余不确定性风险 |
| 风险领域（risk domain） | 描述任务可能通过哪类工程机制失败，用于路由项目 Profile、专业 Skill 和风险对应证据 | 不决定任务级别；同一个 L1 / L2 任务可以命中多个风险领域 |
| Profile | 位于目标项目 `.ai/profiles/` 的短路由契约，定义触发条件、风险领域、必读上下文、最低证据和 Skill 绑定 | 不是长篇培训手册，也不替代项目 `AGENTS.md` |
| 能力包（capability pack） | canonical `extensions/` 中可选安装的 Profile、Skill、references、scripts、training 和示例集合 | 不进入 README First 最小系统；未安装时不增加日常上下文负担 |
| Skill | Agent 按需加载的专业执行能力，负责某一风险领域具体如何设计、实现、审查或教学 | Profile 决定何时加载；Skill 不得覆盖项目本地更严格规则 |
| 风险对应证据 | 直接证明某一风险已被分析、测试或控制的材料，如查询计划、并发测试、权限负面用例和迁移恢复演练 | 不是笼统的“测试通过”，也不是 Scanner 无命中 |
| 候选扫描（candidate scan） | 用静态规则快速定位值得人工或 Agent 继续追踪的高风险位置 | 命中不等于 finding；未命中也不证明安全或正确 |
| 偶然不确定性 | 来自“还没读文件、搜代码或看测试”，可通过工程动作消除 | 与本质不确定性相对 |
| 本质不确定性 | 来自用户意图、业务规则、方案取舍和验收标准，需要访谈、保守假设与记录来压缩 | 与偶然不确定性相对 |
| 验证证据 | `.ai/changes/` 中记录的实际命令、关键输出摘录和结论 | 不是只写验证方式或主观判断 |
| 访谈模式 | 当 L2 任务的关键不确定性只存在于用户脑中时，沿决策树逐层提问并沉淀结论 | 不是把可通过读仓库解决的问题重新抛给用户 |
| 标准扩展 | `.ai/plans/`、`.ai/glossary.md`、`.ai/handoff.md`、`.ai/profiles/`，均按需启用 | 不属于每个项目都必须填满的最小系统 |
| 版本印记 | 下游项目 `AGENTS.md` 首行的 `<!-- README First protocol vX.Y.Z -->` 注释 | 不是根 `VERSION` 文件本身 |
| 热度 × 复杂度 | Builder / Maintainer 选点算法：热度按近 90 天唯一提交计数；复杂度按递归文件数、行数、内部深度与大文件综合评分 | 不是按修改文件条数累计，也不是目录距仓库根的深度 |
| 够用即停 | 当影响当前任务的偶然不确定性已经消除，就停止扩大读取 | 不是读完整个仓库，也不是跳过调用方和测试 |
| 时效戳 | 目录 README 与 `.ai/architecture/` 的 `> 更新于:YYYY-MM-DD`，表示最近一次核验日期 | 旧的 `· commit <sha>` 格式仍兼容，但不再要求，因为编辑时最终提交 SHA 尚不存在 |
| 记忆压缩 | Maintainer 将较早 changes 生成月度 digest，并把原件移动到 archive | 不是删除历史记录 |
| 知识沉淀 | 把重复、已验证的假设、约定、边界或踩坑晋升为 README、architecture 或 decisions | 不是复制所有 changes 流水 |

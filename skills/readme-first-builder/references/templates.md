# README First v2 模板集

供 readme-first-builder 初始化和 readme-first-maintainer 补建时使用。所有模板遵循同一规则:**信息不足的节直接删除,不写空泛占位句;所有内容必须来自当前代码的实际观察。**

---

## 1. 目录 README 模板

最小可用版(顺手补建时,三节即可):

```md
# 目录说明:<目录名>

> 更新于:YYYY-MM-DD · commit <short-sha>

## 职责
本目录负责:
本目录不负责:

## 核心文件
| 文件/子目录 | 作用 |
|---|---|

## 测试与验证
修改本目录后运行:
```

完整版(P0 目录或 maintainer 补全时):

```md
# 目录说明:<目录名>

> 更新于:YYYY-MM-DD · commit <short-sha>

## 职责
本目录负责:
本目录不负责:

## 核心文件
| 文件/子目录 | 作用 |
|---|---|

## 约定与依赖边界
(命名、导出方式;可以依赖什么、不应依赖什么)

## 测试与验证
修改本目录后运行:

## 维护提示
(未来维护者需要知道的长期约定;没有就删掉本节)
```

## 2. `.ai/architecture/README.md` 起步模板(单文件)

```md
# 当前架构状态

> 更新于:YYYY-MM-DD(由变更或维护流程更新)

## 系统概览
(一段话:项目由哪些主要模块组成,数据/控制如何流动)

## 模块地图
| 模块/目录 | 职责 | 主要对外接口 | 验证入口 |
|---|---|---|---|

## 跨目录边界
(哪些依赖方向是允许的、哪些是禁止的;共享类型/配置的权威位置)

## 当前接受的缺口
(已知但暂不处理的问题,避免后续 Agent 反复重新发现)
```

超过约 150 行或出现独立主题时,由 maintainer 拆分为多文件并把本文件改为目录入口。

## 3. `.ai/changes/YYYY-MM-DD.md` 条目模板

L1 短模板:

```md
## HH:MM - <标题> [L1]
- 目标与修改:
- 原因:
- 假设 / 剩余不确定性:(无则写"无")
- 验证证据:(命令 → 关键输出摘录 → 结论;无法运行写明原因与替代核查)
- 文档更新:(无则写"无")
```

L2 完整模板:

```md
## HH:MM - <标题> [L2]
- 用户目标:
- 涉及目录:
- 修改内容与原因:
- 已消除的不确定性:
- 关键假设:
- 剩余不确定性:
- 影响范围 / 风险控制:
- 验证证据:(实际运行的命令 + 关键输出摘录 1–5 行 + 结论;无法运行写明原因与替代核查)
- README 更新:
- 是否新增/更新 .ai/decisions/:
```

L0 不写入 changes,commit message 足够。

## 4. `.ai/decisions/NNNN-<slug>.md` 模板

```md
# NNNN - <决策标题>

## 背景
(是什么问题迫使我们做选择)

## 决策
(选了什么;考虑过但放弃了什么,为什么)

## 影响
(哪些文件/边界/流程因此需要长期遵守什么)

## 非目标
(本决策明确不涉及什么,防止过度引申)
```

## 8. 根 README「项目地图」骨架

合并进目标项目根 README 时,只补缺失的节:

```md
## 项目是什么
## 技术栈
## 安装 / 启动 / 测试 / 构建
## 顶层目录职责
| 目录 | 职责 |
|---|---|
## AI 协作入口
本项目采用 README First 协议:执行任务前先读 `AGENTS.md`(第 0 节最小闭环),
变更记录在 `.ai/changes/`,当前架构见 `.ai/architecture/`。
```

# 05. 事务、锁、并发与幂等

## 学习目标

- 写出事务保护的业务不变量与读写集合；
- 识别丢失更新、先查后写、超卖、死锁和部分失败；
- 使用条件 UPDATE、唯一约束、version、锁与隔离级别；
- 对 `40001` / `40P01` 有界重试整个事务；
- 为命令型 POST、消息和外部副作用建立幂等。

## 并发是默认路径

“先读取，再判断，再写入”在两个请求同时执行时可能失效。常用机制：

- `UPDATE ... WHERE version = $expected`；
- `UPDATE inventory SET available=available-$n WHERE available >= $n`；
- UNIQUE 约束兜底重复创建；
- 短事务 `SELECT ... FOR UPDATE`；
- 必要时 Serializable，但必须处理重试。

锁顺序必须稳定，例如按资源 ID 排序后加锁，避免 A→B 与 B→A 形成死锁。

## 幂等与未知结果

幂等记录至少包含 tenant、key、请求哈希、执行状态、响应和过期时间。同 key 同请求返回原结果；同 key 不同请求返回冲突。数据库提交与消息/邮件/Webhook 发布之间使用 Outbox 或明确的一致性边界。

事务体必须可重放，不要在事务内部执行慢速或不可重复的第三方调用。

## 练习

使用两个独立 PostgreSQL 连接和 barrier 复现丢失更新与死锁；修复后重复运行 100 次，证明最终版本、余额/库存和审计记录满足不变量。再模拟服务端提交成功但响应丢失，证明重复 POST 只产生一次业务副作用。

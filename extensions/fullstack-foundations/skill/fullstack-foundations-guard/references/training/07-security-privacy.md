# 07. 认证、授权、安全与隐私

## 学习目标

- 画出资产、攻击面、数据流和信任边界；
- 区分认证、会话、对象/动作/字段授权和租户隔离；
- 防止 Mass Assignment、注入、SSRF、路径遍历和不安全上传；
- 正确处理 Cookie、Token、浏览器存储、密钥、日志和数据保留；
- 用负面测试而不是“登录成功”证明权限正确。

## 服务端信任边界

客户端传入的 `userId`、`tenantId`、`role`、价格、折扣、所有者、审批状态和字段可见性通常不能作为最终真相。服务端应从已验证会话、服务身份和数据库关系推导权限。

授权至少包含：

```text
actor + tenant/workspace + resource + action + field/scope + current state
```

详情、列表、搜索、导出、附件、活动流、后台任务和缓存都要遵守相同语义。

## 输入与注入

所有边界使用运行时 schema，并限制长度、数量、范围、嵌套和未知字段。SQL 值参数化；动态标识符固定映射；命令优先不用 shell；用户 URL 限制协议/域名并在 DNS 解析后阻断私网、loopback、link-local 和云元数据；上传限制数量/大小、服务端识别内容、随机名、隔离存储和受控下载。

## 会话、秘密和隐私

典型 Web 会话优先评估 `HttpOnly`、`Secure` Cookie、CSRF、轮换、撤销和过期。不要把 access token、完整用户对象或敏感权限长期写入 localStorage。日志默认不记录 Authorization、Cookie、session ID、密码、密钥、连接串、完整请求体和不必要 PII。

隐私还要回答收集目的、字段最小化、保留期限、访问者、第三方共享、导出/修正/删除，以及缓存、分析平台和备份的同步处理。

## 练习

为多租户工作项系统建立权限矩阵和负面测试：未认证、无权、跨租户、字段越权、Mass Assignment、旧缓存、已撤销会话、SSRF、伪造上传和日志脱敏。证明无权主体不能通过任何读取或导出路径获得数据。
